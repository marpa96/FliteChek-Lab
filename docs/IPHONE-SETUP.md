# Install FliteChek on your iPhone

FliteChek is now an installable web app. No Xcode, Apple Developer membership, AltStore or weekly refresh is needed. The app and checklists can work offline once installed and cached.

## Current status

The app runs locally on your Mac and its offline behavior has been tested in an isolated desktop browser at iPhone screen dimensions. It has not yet been tested on your physical iPhone or mobile Safari.

The regular launcher is Mac-only. The iPhone launcher requires a private access link before another device can read the bundled app or checklist files. Nothing is uploaded to an external host.

## Preview on this Mac

Double-click **Start FliteChek.command** in the FliteChek folder. Keep its window open, then open [the local preview](http://localhost:8080/).

This launcher defaults to Mac-only access. Do not open `web/index.html` directly: a `file://` address cannot install the offline app.

## Enable iPhone setup when ready

Double-click **Start iPhone Setup.command** instead of the regular launcher. It runs this command:

```sh
python3 scripts/serve.py --iphone
```

Run it from the FliteChek folder, after stopping any previous launcher with Control-C. This serves app files to devices on your local network that have your private setup link. Keep that link private. It does not send the checklist files to a hosting company. The server serves only `web/`; your browser's edits, backups, private certificate keys and the rest of the project are not served.

Use your trusted home Wi-Fi. Keep the Mac and iPhone on the same network. If macOS asks whether Python may accept incoming connections, allow it for this test. Guest Wi-Fi networks may prevent devices from reaching each other.

## One-time local HTTPS setup

iPhone offline web apps need a secure HTTPS address. This local route creates a certificate on your Mac; you explicitly trust it on your iPhone. It does not install or trust certificates on either device automatically.

1. The launcher prints an **iPhone setup address**, like `http://192.168.1.20:8766/?access=…`. Copy the whole link, including its access code, to your iPhone and open that exact address in Safari on your iPhone.
2. Tap **Download this Mac’s FliteChek testing certificate**. Allow the profile download.
3. Open **Settings → General → VPN & Device Management**, select **FliteChek Local Testing**, and install it. Follow the iPhone's passcode and confirmation steps.
4. Open **Settings → General → About → Certificate Trust Settings**, and enable full trust for **FliteChek Local Testing**.
5. Return to the setup page and tap **Open FliteChek securely**. Its address will look like `https://Your-Mac.local:8443/`.

Only install the certificate generated by your own Mac. The launcher and setup page display its SHA-256 fingerprint for comparison. Trusting a root certificate is a device trust change; keep the generated `.local/` folder private. Remove the FliteChek certificate profile in Settings when you finish local testing. Removing it will prevent secure connections to this local server until trusted again.

Apple's instructions: [Manually installed certificate trust](https://support.apple.com/en-us/102390).

## Add to Home Screen and verify offline use

1. On the secure FliteChek page, choose **Share → Add to Home Screen**. Keep **Open as Web App** enabled if that option appears, then tap Add.
2. Open **FliteChek from the new Home Screen icon** while the launcher is still running.
3. Open **Menu → Setup & backup → Check offline readiness**. Wait for confirmation that app files are saved. This also requests persistent storage, which the browser may or may not grant.
4. Open a checklist and check an item.
5. Enable Airplane Mode, close the app and reopen it from its icon. Verify the same checklist and checkmark return.

The Home Screen app can have separate storage from Safari. Install first, then make your real edits inside the installed app. If you edited in Safari, use **Download full backup**, then restore that file inside the Home Screen app.

Apple's instructions: [Add a website as an app](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

## Everyday testing

- Once offline files are saved, the Mac does not need to remain running to use the installed app offline. It is needed for first setup, recaching and updates.
- Always use the same hostname and port. A numeric IP address, another hostname, another browser or another device has separate app storage.
- Checking items, drafts and revisions save on the device. Use **Menu → Setup & backup → Download full backup** regularly. That includes versions and progress; individual Markdown export contains checklist content only.
- The app deliberately does not prompt you to update during a checklist. New service-worker releases wait until app windows close. Developers must change the cache version when shipping a new release.
- If site data is cleared, storage is evicted, or the app is removed, you may need to reconnect, recache, and restore a backup. See [WebKit's storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/).

## If something does not work

- **“Opening your checklists…” never finishes:** use the server address, not a file opened in Finder. Check that the launcher window is still running.
- **The iPhone cannot open the setup page:** confirm the iPhone launcher is running, both devices share the same network, and the Mac firewall permits this server.
- **HTTPS is not trusted:** installing the certificate and enabling full trust are separate steps. Check both. Do not proceed through a certificate warning and assume offline installation will work.
- **`.local` does not resolve:** some networks block local-name discovery. A launcher-provided IP can be used as a separate test origin, but its saved data will be separate and an IP change will require another setup. Prefer a stable `.local` address or a future stable HTTPS host.
- **Port already in use:** stop the earlier launcher with Control-C before starting another.
- **Offline-ready does not appear:** open Setup & backup and check readiness for the error message. Keep the app connected until all files are cached.

A publicly hosted HTTPS version could remove the local certificate setup. That would require a separate decision about uploading your bundled checklist content. This prototype has not been published.
